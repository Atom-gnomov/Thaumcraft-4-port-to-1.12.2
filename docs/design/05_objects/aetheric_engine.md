# Эфирный Двигатель · Aetheric Engine

| | |
|---|---|
| **Registry** | `unboundtech:aetheric_engine` |
| **Тип** | блок с тайлом |
| **Тир** | T3 |
| **Акт** | IV. Резонанс |
| **Статус** | ✅ реализовано (сабмод 0.2.1) |
| **Класс** | `unboundtech.common.blocks.BlockAethericEngine` / `unboundtech.common.tiles.TileAethericEngine` |

## 1. Зачем это существует

Вторая половина энергомоста и единственный в игре способ **вернуть** узлу
силу быстрее, чем он лечится сам. Превращает узел из невозобновляемого
ресурса в возобновляемый — и тем снимает главный страх мага перед
машинами: «они выпьют мой узел».

## 2. Место в мире

- **Кому нужен:** магу (лечит узлы), технику (даёт применение избытку EU,
  когда реактор уже гонит больше, чем нужно).
- **Что открывает:** ничего напрямую; закрывает контур энергомоста.
- **Что требует:** `VIS_TO_EU_GENERATOR` (сначала научись брать, потом
  возвращать), продвинутая схема IC2 как ядро.
- **С чем взаимодействует:** узлы ТК, энергосеть IC2 (как потребитель),
  Таум-Генератор (образуют пару у одного узла).
- **Что заменяет/дополняет:** аналогов нет ни в ТК, ни в IC2. Ближайший
  родственник по смыслу — «энергизация» узла в ТК, но там это одноразовый
  ритуал, а не поток.

## 3. Лор

Гнать силу обратно в гору дорого: четыре единицы тока за каждую, что
генератор когда-то выдал. Двигатель заливает истощённый узел сырой мощью,
а аура сама лепит из неё тот аспект, которого узлу недостаёт. Расточительно
— и стоит того: узел, которому на самолечение нужен час, наполняется за
минуту.

## 4. Механика

- **Периодичность:** попытка долива — раз в **20 тиков**.
- **Радиус действия:** куб **±8** блоков.
- **Условия работы:** в буфере ≥ 8 000 EU; в радиусе есть узел, у которого
  хотя бы один аспект ниже своей ёмкости.
- **Условия отказа:** буфера не хватает (машина ждёт подачи); все узлы
  полны. Причина видна по ПКМ.
- **Пределы:**
  - **Ёмкость узла (`aspectsBase`) не трогается никогда.** Двигатель
    доливает только недостающее до текущей ёмкости; вырастить узел или
    воскресить угасший (FADING) он не может — это отдельная тема поздних
    тиров.
  - Аспект для долива выбирается случайно из недостающих — так же, как это
    делает собственная регенерация узла.

## 5. Числа

| Параметр | Значение | Источник |
|---|---|---|
| Буфер EU | 40 000 | собственное (5 порций) |
| Приём | до 128 EU/t | тир MV IC2 |
| Тир напряжения | MV (2) | ❗ подача выше MV взорвёт машину — как у машин IC2, намеренно |
| Долив | 1 аспект / 20 тиков | собственное |
| Цена долива | 8 000 EU за аспект | канон §3.1 |
| Практическая скорость | ~1 аспект / 2.5 сек на полном MV-подводе | расчёт: 8 000 / 128 EU/t |
| Радиус узлов | 8 | |
| Прочность / сопротивление | 3.0 / 15.0, кирка ≥1 | |
| Свет при работе | **7** (как у работающего генератора IC2) | `machine_feedback.md` §4 |

Соотношение с генератором: 8 000 / 2 000 = **цикл 25%** — закон 2 соблюдён.

## 6. Рецепт

- **Верстак:** арканный.
- **Сетка:**
  ```
  T S T      T — закалённый таумий (в коде 0.2.x временно обычный, §12)
  T C T      S — осколок Ordo
  . Q .      C — Продвинутая схема IC2
             Q — Ртуть (проводник ауры)
  ```
- **Аспекты крафта:** `Ordo 25`, `Perditio 25`, `Aer 25`.
- **Исследование-владелец:** `EU_TO_VIS_ENGINE`
  (стоимость: `Potentia 10`, `Auram 8`, `Permutatio 6`, `Ordo 4`).
- **Альт-рецепты при аддонах:** нет. Без продвинутой схемы IC2 рецепт не
  регистрируется.

## 7. Аспекты объекта

По формуле (`04_systems/aspect_economy.md`). Ожидаемый итог:
`Machina ~10, Metallum ~8, Ordo ~6, Auram ~4` — Auram появляется из
подписи процесса и ртути, отличая двигатель от генератора.

## 8. Визуал

- **Модель:** как у генератора — `block/orientable`, 4 поворота × 2
  состояния, алфавитные ключи блокстейта.
- **Текстуры:** общий корпус (`machine_*`) + `aetheric_engine_front`,
  `aetheric_engine_front_active`.
- **Состояния:** «морда» светится холодным (голубым) при работе —
  визуальный контраст с тёплой (пурпурной) мордой генератора: по цвету
  сразу видно, кто берёт, а кто отдаёт.
- **Анимация:** родные частицы вис **от машины к узлу** — зеркало
  генератора, направление потока читается без GUI
  (`machine_feedback.md` §3).
- **Индикаторная полоска:** та же трёхцветная схема (§2 там же).
- **Как читается силуэт:** тот же корпус, что у генератора, отличается
  только мордой — намеренно: это парные машины одной линейки.

## 9. Взаимодействие с игроком

- **ПКМ пустой рукой:** строка статуса (буфер EU).
- **GUI:** нет.
- **Гогглы:** EU-параметры и канал вис (`machine_feedback.md` §6.2).
- **Обратная связь при простое:** различается цветом полоски —
  🔴 «недостаточно энергии», 🔵 «все узлы полны»; текст причины по ПКМ.

## 10. Крайние случаи

| Ситуация | Поведение |
|---|---|
| Подача выше MV | Взрыв (штатное поведение IC2) — задокументировать в лоре |
| Узел полон | Простой без расхода EU |
| Узел FADING | Доливается до его (пониженной) ёмкости; ёмкость не растёт |
| Чанк с узлом выгружен | Пропуск позиции, чанк не грузится |
| Рестарт / смена ACTIVE | Буфер в NBT, тайл переживает смену состояния |
| Пара «генератор + двигатель» у одного узла | Работает, но убыточна (25%) — это и есть защита от вечного двигателя |
| Блок сломан киркой / разобран ключом | Пусто / с сохранённым буфером (`machine_feedback.md` §5) |

## 11. Приёмка

1. Подать MV на двигатель у истощённого узла — недостающие аспекты
   доливаются примерно раз в 2.5 секунды.
2. Ёмкость узла (`aspectsBase`) не меняется ни при каких условиях.
3. Полный узел — машина не тратит EU.
4. Пара генератор↔двигатель у одного узла: суммарный баланс EU
   отрицательный (замерить за 5 минут).
5. Подать HV — машина взрывается (ожидаемо), лор это оговаривает.
6. Перезаход в мир — буфер сохранён.
