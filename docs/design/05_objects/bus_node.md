# Шинный Узел · Bus Node

| | |
|---|---|
| **Registry** | `unboundtech:bus_node` |
| **Тип** | блок |
| **Тир** | T3 |
| **Акт** | IV. Резонанс |
| **Статус** | 🔜 спроектировано |
| **Класс** | `unboundtech.common.tiles.TileBusNode` (планируется) |

Система целиком описана в `04_systems/essentia_logistics.md`; здесь —
карточка одного объекта.

## 1. Зачем это существует

Труба ТК несёт **один аспект за раз** и работает на тяге потребителя.
База на 15–20 аспектов превращается в спагетти. Узел — вход и выход
многоканальной шины: он сам вытягивает эссенцию из обычных труб в
поканальные буферы и гонит её по кабелю.

## 2. Место в мире

- **Кому нужен:** магу с большой алхимией; питается от техники.
- **Что открывает:** `ESSENTIA_VAULT` (накопитель).
- **Что требует:** `TEMPERED_THAUMIUM`, энергосеть, кабель шины.
- **С чем взаимодействует:** трубы ТК, наш кабель, накопитель, любые
  `IEssentiaTransport`-устройства.
- **Что заменяет/дополняет:** не заменяет трубы — стоит на их концах.
  Зеркала эссенции ТК решают другую задачу (снабжение крафтеров, см.
  `essentia_logistics.md` §1) и остаются за ними.

## 3. Лор

«Труба честна и глупа: она несёт то, что тянут, и молчит об остальном.
Узел — это перекрёсток, которому объяснили расписание. Он держит в себе
по глотку каждого смысла и отправляет их по одной нити, не давая
перепутаться, — за что и требует своей платы током».

## 4. Механика

- **Периодичность:** обслуживание каналов — раз в **10 тиков**.
- **Радиус действия / зона:** [N/A] — только соседние блоки.
- **Условия работы:** есть EU, подключён кабель, есть тяга на том конце.
- **Условия отказа:** нет EU → перекачка встаёт, буферы сохраняются, 🔴;
  каналов меньше, чем подключённых труб → лишние не обслуживаются, 🔴 с
  пояснением «каналов не хватает: 5 труб, 4 канала».
- **Пределы:** до **5 сторон** под трубы (шестая — кабель); один канал на
  трубу; буфер **8 единиц на канал**.

### 4.1. Направление

Отдельных «входных» и «выходных» узлов нет: направление определяется
соседями — узел смотрит на **тягу**. Если рядом потребитель объявил тягу,
узел отдаёт; если рядом источник — тянет.

⚠️ Прежняя редакция обосновывала это словами «как трансвекторы ТК» —
неверный прецедент. Трансвектор
(`TileTransvectorInterface`) — это **прокси**: он подставляет вместо себя
другой блок в радиусе 4 и пересылает ему запросы. Направления он не
выбирает и тягу не читает вовсе.

Правильный прецедент — **эссенциальные трубы** ТК
(`TileTube` + `IEssentiaTransport`): именно там четыре метода
`canInputFrom` / `canOutputTo` / `getSuctionType` / `getSuctionAmount`
задают «кто тянет и что именно», и направление сегмента вытекает из
соседей, а не из настройки блока. Наш узел реализует **тот же
интерфейс** и потому ведёт себя для игрока как труба без трубы — это и
есть обоснование.

### 4.2. Порядок обслуживания

Строго **алфавитный по тегу аспекта** (`AspectList.getAspectsSorted()` в
ТК уже даёт этот порядок). Никакого «повезло»: две одинаковые сборки
ведут себя одинаково, и это же правило действует у накопителя и
Индукционного Тигля.

## 6. Рецепт

- **Верстак:** арканный.
- **Сетка / компоненты:**

```
 T      T — слиток закалённого таумия ×3
TUT     U — Труба ТК (blockTube)
 G      G — стекло
```

- **Аспекты крафта:** `Ordo 9`, `Aer 7`, `Aqua 4` — только примордиалы.
  ⚠️ Пересчитано по `recipe_calibration.md` §4: было `Ordo 20`, `Aer 15`, `Aqua 10` (45 вис) —
  в 2.2 раза выше эталона ТК. Пропорции и главный примал сохранены.
- **Исследование-владелец:** `ESSENTIA_BUS` (T3), родитель —
  `TEMPERED_THAUMIUM`. Стоимость: `Permutatio 10`, `Machina 10`,

- **Альт-рецепты при аддонах:** нет.

## 7. Аспекты объекта

По формуле; профиль: `Metallum ~7, Ordo ~4, Vitreus ~3, Machina ~3`.
⚠️ Профиль, а не расчёт — точные числа из лога.

## 8. Визуал

- **Модель:** невысокий блок-коробка с патрубками на каждой стороне, где
  подключена труба (модель меняется по соединениям, как у труб ТК).
- **Текстуры:** `blocks/bus_node_{side,port}.png` + индикаторная полоса.
- **Состояния:** простой (полоса 🔵), работа (🟢, бегущие огоньки по
  патрубкам), отказ (🔴).
- **Анимация:** родные частицы эссенции ТК цвета текущего аспекта,
  проскакивающие от патрубка к кабелю.

## 9. Взаимодействие с игроком

- **ПКМ пустой рукой:** статус — список каналов «аспект: сколько/8» и
  предупреждение, если труб больше, чем каналов.
- **Shift-ПКМ ключом:** разборка с сохранением буферов.
- **GUI:** нет.
- **Гогглы:** содержимое каналов и EU-слой.

## 10. Крайние случаи

| Ситуация | Поведение |
|---|---|
| Труб больше, чем каналов кабеля | Лишние не обслуживаются, статус называет число |
| Кабель сломан посередине | Обе половины работают как отдельные линии |
| Кончилось EU | Встаёт, буферы целы |
| Чанк с частью линии выгружен | Через границу выгруженного чанка перекачки нет (не форсим загрузку) |
| Два узла тянут один аспект | Алфавит, затем порядок подключения — детерминированно |
| Сломан киркой | Содержимое буферов теряется |
| Сервер перезапущен | Буферы в NBT |

## 11. Приёмка

1. Две трубы с разными аспектами в узел, кабель II тира → оба аспекта
   идут по одной линии.
2. Подключить пятую трубу к кабелю I тира (2 канала) → 🔴 и точный текст.
3. Обесточить → перекачка встала, эссенция в буферах на месте.
4. Разобрать ключом → буферы сохранены.
5. Поставить два узла на один аспект → порядок обслуживания стабилен
   между перезапусками.

## 12. Открытые вопросы

1. ⚠️ Цена 20 EU за единицу — предварительная (`essentia_logistics.md`
   §7.2): проверить в игре, не окажется ли шина дороже пользы.
2. ❓ Периодичность 10 тиков против «тяги» труб ТК: если окажется, что
   шина заметно медленнее трубы на коротком плече, поднять до 5.
