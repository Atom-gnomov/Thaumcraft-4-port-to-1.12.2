# Таумиевый ключ · Thaumium Wrench

| | |
|---|---|
| **Registry** | `unboundtech:thaumium_wrench` |
| **Тип** | предмет (инструмент) |
| **Тир** | T2 |
| **Акт** | III. Изоляция |
| **Статус** | 🔜 спроектировано |

## 1. Зачем это существует

Функциональный близнец бронзового ключа IC2 — но для мага. Смысл не в
механике, а в доступе: игрок, пришедший со стороны ТК, не должен строить
бронзовую металлургию только ради того, чтобы переставить машину.

Это единственное исключение из правила «инструментов не делаем»
(`01_vision.md` §4): ключ — не инструмент добычи, а ключ доступа к
собственному контенту.

## 2. Место в мире

- **Кому нужен:** магу в первую очередь.
- **Что требует:** обычный **таумий** (не закалённый — намеренно: ключу
  нужна гибкость живого металла, а не жёсткость закалённого).
- **С чем взаимодействует:** наши машины (гарантированно), машины IC2 (❓ §10).

## 3. Лор

Таумий помнит форму. Его не нужно подгонять под гайку — он подгоняется
сам, стоит приложить и пожелать. Инженеры, впервые увидев работу такого
ключа, обычно говорят что-нибудь про допуски и посадки, а потом просят
сделать второй.

## 4. Механика

ПКМ по нашей машине — снимает её с сохранением содержимого (буфер EU,
направление). Поведение полностью повторяет бронзовый ключ IC2, включая
шанс потери при разборке.

## 5. Числа

| Параметр | Значение |
|---|---|
| Прочность | 200 использований |
| Шанс успешной разборки | как у бронзового ключа IC2 (не переопределяем) |
| Материал починки | `ingotThaumium` |

## 6. Рецепт

- **Верстак:** обычный (ключ — вещь ремесленная, не ритуальная).
- **Сетка:** как бронзовый ключ IC2, но из таумия.
- **Исследование-владелец:** `TEMPERED_THAUMIUM` (идёт в комплекте с
  материаловедением — отдельной записи не заслуживает).

## 7. Аспекты объекта

Рецепт повторяет ключ IC2 — `"B B|BBB| B "`, то есть **6 слитков**
(проверено по `assets/ic2/config/shaped_recipes.ini`). Из слитка
`Metallum 2, Ignis 2, Praecantatio 1`, обычный верстак — подписи нет:

**Итог: `Metallum 7, Ignis 7, Praecantatio 4`.**

`Instrumentum` руками не добавляем (`aspect_economy.md` §2.6): ТК приписывает его
инструментам сам — но только классам `ItemTool`; если ключ будет обычным
`Item`, его не появится, и это нормально.

## 8. Визуал

- Силуэт бронзового ключа IC2, но лиловый металл ТК с лёгким свечением.
- Модель `item/handheld`.
- Анимация: нет.

## 9. Взаимодействие с игроком

- ПКМ по машине — разборка.
- Тултип: явно указать, работает ли ключ на машинах IC2 (см. §10) —
  игрок не должен выяснять это методом тыка.

## 10. Крайние случаи

| Ситуация | Поведение |
|---|---|
| ПКМ по машине IC2 | ✅ **Решено (§12).** Контракт есть и он на стороне **блока**: `ic2.api.tile.IWrenchable` с четырьмя методами по `(World, BlockPos)`. Наш ключ зовёт ровно их, значит разбирает и машины IC2, и наши одинаково. Отдельного «этот предмет — ключ» в IC2 нет и не нужно |
| ПКМ по чужому блоку | Ничего |
| Прочность кончилась | Ломается как обычный инструмент |

## 11. Приёмка

1. Разбирает наши машины с сохранением буфера.
2. Разбирает **машину IC2** (например электропечь) через `IWrenchable`:
   поворот, снятие, дроп с буфером — как бронзовым ключом.
3. Тултип честно описывает область применения.
4. Чинится таумием.

## 12. Открытые вопросы

1. ✅ **РЕШЕНО (аудит T1–T4):** интерфейс есть и публичный —
   `ic2.api.tile.IWrenchable`, и реализует его **блок**, а не тайл:
   все методы принимают `(World, BlockPos)` (`getFacing`, `setFacing`,
   `wrenchCanRemove`, `getWrenchDrops`). Значит `IWrenchable` вешается на
   наш `BlockMachineBase`, а таумиевый ключ зовёт те же четыре метода,
   что и бронзовый ключ IC2. Дроп с сохранённым буфером отдаёт
   `getWrenchDrops`.
